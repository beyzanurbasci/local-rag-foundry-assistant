Foundry Local is a developer-centric SDK designed to execute AI models locally on consumer-grade hardware. By eliminating cloud dependencies, Foundry Local guarantees data sovereignty, removes external API costs, and enables high-performance inference in offline environments. It leverages the ONNX Runtime for hardware-agnostic acceleration, ensuring models run efficiently across various CPU and GPU architectures.

Retrieval-Augmented Generation (RAG) is a sophisticated architecture that bridges the gap between static LLM knowledge and dynamic, private data. Unlike standard LLMs which rely on training data cutoff, a RAG pipeline dynamically fetches relevant information from a vector database before generating an answer. This "grounding" process minimizes hallucinations by constraining the model to the provided context chunks.

The ingestion pipeline in a RAG system involves several critical steps. First, raw documents are cleaned and normalized. Then, they undergo "chunking"—splitting large texts into semantic passages of 1-3 paragraphs to ensure embedding models capture focused context. These chunks are converted into multi-dimensional vectors using specialized embedding models like qwen3-embedding-0.6b.

Vector similarity search is the mathematical engine of RAG. Once query vectors are generated, the system performs a cosine similarity calculation against all stored vectors in the SQLite database. Cosine similarity measures the cosine of the angle between two vectors in a multi-dimensional space, effectively quantifying the semantic closeness between the user's intent and the stored documentation chunks.

Best practices for building robust RAG applications include: 1) Optimizing chunk size for specific domain knowledge; 2) Implementing clear system prompts that explicitly instruct the model to use only the provided context; 3) Using strict grounding instructions to ensure the model admits when it lacks information, rather than inventing it.

Effective system prompts follow a specific hierarchy. The System Role defines the persona, constraints, and operational boundaries (e.g., "Do not use external knowledge"). The User Role delivers the dynamic query, and the Context block serves as the source of truth for the response. This separation ensures the model treats the context as a reference manual rather than a conversational suggestion.
